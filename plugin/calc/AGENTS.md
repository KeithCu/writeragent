## Sharp edges

- `=PROMPT()` must not `processEventsToIdle` during recalc (`run_blocking_in_thread(..., pump_idle=False)`). Pumping re-enters the formula engine (`#VALUE!`). `=PY()` already blocks without a VCL pump.
- `=PY()` gets the calling **document** from LibreOffice's hidden caller argument (`XPropertySet` first parameter in `XPythonFunction.idl`); that is the only source. No front-window guess, open-documents search, or last-active cache; a missing caller returns `Error: no calling document`. The calling **cell** is still unknown: spill/image only when `locate_formula_cell_in_doc` finds a **unique** formula origin in that document (located once in `build_cell_context` and carried as `CellContext.origin` / `is_matrix`; `spill.prepare_auto_spill` takes that origin and does not locate again). Off-main the doc is only passed through (no UNO on it): no shared session id or init kwargs there, and locate + write for auto-spill are posted to the UI thread.
- Spill, listeners, and geometric recalc state use `WorkbookState.key` (RuntimeUID, else the one remembered lifecycle id). The file URL is not a key. `calc:unsaved:{uuid}` is still only the worker session id. Spill orphan cleanup saves `WriterAgentSpillRegistry` on the sheet's owner, not the focused window.
- Spill records are one rectangle per formula cell (`SpillRecord(code, rows, cols)`), no cell values. A record whose formula moved is remapped only when there is a single match on the sheet and the sheet's used-area end (`gotoEndOfUsedArea`) moved by the same delta (`state.used_ends`); otherwise it is dropped (or kept if the origin still holds a `=PY` formula and the used-area end grew without shrinking, `delta[0] >= 0 and delta[1] >= 0 and delta != (0, 0)`). Deletion clears the rectangle only when there are zero matches on the sheet, the formula was seen at its origin this session, `delta == (0, 0)`, the origin is now empty or a `=PY` formula, and no user formula is inside. A user formula (text other than our error literals) inside the rectangle blocks the spill.
- LibrePy uses `addin_librepy.py` instead of `addin.py`.
- Collabora Online `=PY()` files store `…PYTHONCOMPUTEFUNCTIONS.GETPY`; on open LibrePy rewrites that prefix ([`python/collabora_formula.py`](python/collabora_formula.py)). Do not register Collabora’s UNO service from the OXT.
- Nested specialized sets use `specialized` / `specialized_control` and are omitted from default main-chat lists. Callers use `delegate_to_subagent`.
- `float(...)` inside `=PYTHON("...")` formula strings → Calc lexer `#NAME?`. Use code-in-cell or bare `np.sum` (see enabling-numpy doc).
- Calc string literals have no backslash escapes. `write_range` and `evaluate_formula` pass `=PY` text through `formula_edit.repair_py_code_newlines`, which turns a literal backslash-n outside Python strings into a line break only when the result parses. Monaco and user-typed cells are not rewritten.
- In tests, resolve tools with `plugin.app.get_tools().get("tool_name")`.
- Sheet names starting with `_` (xlsx→ods `__Anonymous_Sheet_DB__*`, etc.) stay in the workbook. Omit them from agent-facing lists (`sheet_list`, `get_sheet_summary`, chat context, `named_range_list(scope="all")`, unqualified named-range fallback, `pivot_table_list`, and a bare pivot name in `pivot_table_refresh` / `pivot_table_delete` along with their `similar` names). `pivot_table_create` still refuses a name used on any sheet. Do **not** delete them at trial/document open (parked).
- Named-range rename must reject names `ScRangeData::IsNameValid` would reject (`A1`, dots, leading digits, spaces) before `setName`. `addNewByName` already validates; `setName` does not. A bare name in `named_range_get_info`, `named_range_edit`, and `named_range_delete` prefers the active sheet's local range over a same-spelled global name. Explicit `scope="global"` or a sheet name still forces that container. `sql_query_folder`, `CalcBridge.resolve_range_or_address`, and `CalcBridge.resolve_cell` use `CalcBridge.find_named_range` in this order (`set_style`, the comment tools, `named_range_create_from_titles`, and chart `data_range` accept a named range; comments need a one-cell name).
- A missing sheet name is `CalcBridge.get_sheet`'s `UnoObjectError`: `No sheet named '…'. Available: …`. `get_active_sheet` raises `UnoObjectError` for a non-spreadsheet or sheet-less document. Every Calc tool lets it reach `execute_safe`; `cells._mutate_ranges`, `charts._raise_chart_op_error` and `manipulator._write_errors` pass any `WriterAgentException` through with its code and details.
- `=PY()` formula errors are payload NaNs (`calc_formula_error_double`) or, for spill neighbors, `None` / `=#ERRxxx!` in `perform_deferred_spill`. Do not turn those back into `"Error: …"` text. Do not map tokens inside `to_calc_compatible`. A helper error dict (`status` / `code` / `message`, optional `helper` and `details` only) is mapped in `py_addin_cell_value`, not in `to_calc_compatible`. A failed worker run is text only for `VENV_NOT_FOUND`, `VENV_TIMEOUT`, `EXECUTION_TIMEOUT`, and `USER_STOPPED`, decided in `addin_values.addin_result_for_worker_status`; every other code is a payload NaN. `=PY` array writes refuse such text via `addin_values.is_failed_run_text` (a nested `=PY` array write refuses on `addin_values.has_setup_failure_text` in any result cell) and ordinary `=PY` writes warn through `is_failed_run_text`.
- Cell `VertJustify` takes `CellVertJustify2` ints. A `CellVertJustify` enum silently becomes STANDARD (see `manipulator._VERT_JUSTIFY`).
- A Calc tool answers `INVALID_PARAM` when it refuses what the caller passed, including a passed value the workbook makes unusable (a taken name, the last sheet). A non-empty result area answers `SPILL_BLOCKED` (details `needed_range`, `blocking_cells`, `blocking_count`). A `=PY` written inside its own data argument—including an `array=true` block, the block a one-cell array write grows into, or a `=PY` nested inside an array write—answers `PY_CIRCULAR`, with a `suggested_call` to a free column on the right (or a free block for an array block). A delete that would turn formulas or named ranges into `#REF!` answers `REFS_WOULD_BREAK` (details `sheet`, `refs_broken`, `broken_cells`, plus `broken_names` `{name, scope}` when a named range breaks; `refs_broken` counts both) after rolling back; `confirm=true` keeps it and reports the same fields. A failure after the inputs resolved keeps the file's code or `TOOL_EXECUTION_ERROR`. `UnoObjectError` means a UNO object or interface was missing; the one argument case is the bridge's missing-sheet / unresolvable-name miss, which keeps `UNO_OBJECT_ERROR` because it carries the sheet list.
- Calc writes that take several UNO calls (`_mutate_ranges`, `named_range_edit`, `pivot_table_create`, `insert_cell_html_rich`, and the tabular/vision egress writers) run inside `compound_undo.UndoStepOrRollback`. Refuse with error dicts before the bracket opens; inside it, raise.
- All new-plot placement and `=PY` image notes run under `undo_lock(doc, hide=False)`; a plot without a formula adds its own entry with `add_undo_action`. Do not wrap placement in `UndoStepOrRollback`, because `SvxDrawPage::add` is not undoable and undoing only strips the slot name.
- `write_range` quotes the `=PY` cell's newest diagnostics entry from this write for `Err:` and `#SPILL!`, and a blocked spill records its needed range there. Array writes quote the entry too.
- Calc tool success results come from `make_tool_ok` (`plugin/framework/errors.py`), not `{"status": "ok"}` dict literals. Exempt paths: the parked `analysis.py`, `python/function.py`'s worker cache, the import dialog's `spreadsheet_import/`, and `excel_py_convert/`.
- Range borders go through `TableBorder2` in `manipulator._apply_borders`; per-side `TopBorder2` on a range boxes every cell.
- `set_style` number-format codes are en-US converted with `addNewConverted`; never `queryKey` an English code in the document locale.
- In Calc tool paths, `/formula`, `plugin/calc/editselection.py`, and `plugin/writer/specialized/embedded.py`, model formula text reaches `setFormula`/`setArrayFormula`/`Formula1`/named-range content only through `formula_dialect.to_api` (`CellManipulator` caches `FormulaDialects` behind it); never add text-level `,`→`;` or `!`→`.` rewrites; a formula that parses as Calc grammar is written unchanged; model-visible text never advertises Excel syntax.
